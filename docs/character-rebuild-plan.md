# 人物与换装系统重做方案

调研日期：2026-10-21。用户已确认需要人物旋转、转身和摆动作。

## 结论

建议将人物层重做为 **Blender 制作的 Q 版模块化模型 + 统一人形骨架 + VRM/glTF 素材 + Three.js / three-vrm 网页运行时**。CharacterStudio 作为部件管理和遮挡处理的开源参考，先验证其当前依赖与我们的素材兼容性，再决定采用哪些实现。

正式入口 `dist/index.html` 使用原游戏的完整布局及功能，直接使用 `dist/app.js` 和 `dist/style.css`，通过 `dist/doll3d.js` 替换场景中的人物。`dist/character.html` 保留独立预览，`dist/classic.html` 保留原二维人物作回归对照。

原游戏仍管理脸、发、妆、衣、鞋、资源、解锁、撤销、随机、家具和二合进度；3D 渲染器只消费搭配状态。角色包含统一的 24 根骨骼、短发与八款长发网格、四种服装基础网格、鞋及手部部件，以及待机、挥手、走路动作。原来的 16 种发型、8 种脸/妆/衣/鞋选项分别映射至对应网格与材质。用户已查看并授权发布恢复像素化尝试之前的材质、保留圆润头型的版本。

美术第三版重新制作了角色和服装的手绘风多视图素材，并将头发改为连续、圆润的封闭网格。`dist/doll-paint.js` 将这些绘画细节映射到实际绑定骨骼的曲面；转身和动作仍由立体网格完成。身体与手部独立着色，颈部以下的皮肤不再采样整个人物图，避免把素材里的手再次画在模型上。换发色同时处理脸部表面上衔接的刘海颜色。

素材、工具和最终提示词见 [美术制作记录](../art/character/reference/prompts.md)。网页的绘画材质由运行时设置，Blender 文件保存网格、权重、基础材质和动画。

**发布确认：用户已于 2026-10-21 明确授权推送。** 本地启动：`python3 -m http.server 4186 --directory dist`，访问 `http://localhost:4186/`。

本地自动检查已通过 VRM 几何与权重、全部现有搭配选项、三种骨骼动作、旋转与触屏操作、原版保存与图片导出、家具与二合流程，以及 320 / 390 / 815 / 1440 宽度下与原版页面区域尺寸逐项对照。该检查使用桌面 Chrome 和触屏模拟，尚未完成手机实机性能验证。

手部回归检查会暂停动作，并将身体引用图临时替换成纯绿色纹理：双手的实际渲染像素必须完全不变。这验证皮肤表面不再受到引用图中手臂或手的图案影响。

## 候选方案

| 方案 | 适用情况 | 对本项目的判断 |
| --- | --- | --- |
| Spine 2D 骨骼 + Skins | 保持二维插画风，部件替换、动作和有限的立体感 | 有成熟的换装例子；真实连续转身需要另做多视角素材，不作为这次重做的主路线 |
| Blender + GLB + Three.js | 自定义模型、骨骼动画和换装，自己定义素材规范 | 可行；适合完全定制 Q 版形体，但表情和发梢动态需要自行组织 |
| Blender + VRM + Three.js / three-vrm | 使用人形骨骼、表情、视线、弹簧骨等现成约定 | 推荐；同时保留自制模型的外观自由度 |

Spine 官方换装示例支持独立皮肤、服装骨骼与网格；它仍是二维素材驱动的系统。[官方示例](https://eu.esotericsoftware.com/spine-examples-mix-and-match)

VRM 基于 glTF，可用于网页；three-vrm 提供人形骨骼、表情和弹簧骨相关能力。[VRM 概述](https://vrm.dev/en/vrm/vrm_about/) · [three-vrm API](https://pixiv.github.io/three-vrm/docs/classes/three-vrm.VRM.html)

## 人物结构

- **骨架**：统一骨骼名称、层级、单位、初始姿势和绑定规则。骨骼负责运动，网格上的权重决定身体与衣服如何变形。
- **身体**：头、躯干、手臂、手、腿、脚可做成独立网格。相连位置必须使用一致的边界、法线与权重；体型微调用形态键。接缝规则属于我们自己的素材标准，VRM 不会自动提供。
- **脸与妆容**：表情使用形态键；瞳色、肤色和妆容可使用材质、贴图或局部覆盖。图片仍可作为表面纹理和衣橱缩略图。
- **头发**：每款是具有正侧背体积的完整模型，绑定头部；长发额外设置发束骨骼。前发与后发来自同一套设计，避免二维画面中的拼接问题。
- **服装与鞋**：独立网格绑定同一骨架；更换服装时按规则隐藏被覆盖的身体区域，减少身体穿出衣服。衣服之间仍需做搭配和动作适配。
- **饰品**：发夹、耳饰等挂到明确的骨骼或连接点。

Three.js 的 SkinnedMesh 需要骨架、骨骼索引与权重；换成骨骼方案不等于任意模型可以无缝互换。[SkinnedMesh](https://threejs.org/docs/pages/SkinnedMesh.html)

“任何人体部位都能换”应定义为：**符合这套角色规范的部件可以互换**。不同来源、不同骨架和比例的模型，需要先适配；新体型也需要对应的服装适配。裙摆坐下、抬腿等姿势必须专门检查，弹簧骨本身不保证不会穿模。

## 可借鉴的成熟实现

- [CharacterStudio](https://github.com/M3-org/CharacterStudio)：网页角色部件选择、动画、GLB/VRM 导出、网格与贴图优化，以及衣物下面的面片遮挡。项目代码采用 MIT 许可；模型素材的许可需分别确认。
- [CharacterStudio 素材制作规范](https://m3-org.github.io/characterstudio-docs/docs/Modders/process-avatars/)：围绕带骨架的基础人体制作部件，确保位置和比例能正确合并。该文档含旧版本工具说明，实施时需验证当前版本兼容性。
- [CharacterStudio 部件清单](https://m3-org.github.io/characterstudio-docs/docs/Modders/manifest-files/character-traits/)：部件分组、互斥条件、遮挡层与颜色/贴图选项的参考。
- [three-vrm](https://github.com/pixiv/three-vrm)：Three.js 上的 VRM 运行时，代码采用 MIT 许可。
- [VRM Add-on for Blender](https://github.com/saturday06/VRM-Addon-for-Blender)：在 Blender 中编辑、导入和导出 VRM。

这些资料证明路线具备成熟组件，不代表已经在本项目接入成功。CharacterStudio 的演示入口是 [官方 Demo](https://studio.m3org.com/)，本轮核实了官方入口及文档，未做完整运行和移动端测试。

## 美术取舍

保留大头小身、粉色、柔和卡通材质的方向，先做好正面、侧面、背面的造型。3D 角色不会自动保持原图逐像素的绘画效果；像素化应在完整模型好看之后单独评估。

正交相机有助于保持类似换装立绘的比例；Three.js 也有像素化后处理，但它不能替代角色美术制作。[OrthographicCamera](https://threejs.org/docs/pages/OrthographicCamera.html) · [RenderPixelatedPass](https://threejs.org/docs/pages/RenderPixelatedPass.html)

现有 PNG 人物可保留作比例和配色参考，不能当作已经具备背面、拓扑和绑定权重的模型。实际工作量主要在基础角色、头发、服装的建模与适配。

## 分阶段验证

1. **独立人物验证页**：一个正式 Q 版基础角色，支持拖动旋转 360°；有待机、挥手和走路动作。验收：侧面和背面有真实体积，动作时关节正常。
2. **最小换装集合**：两款头发（含一款长发）、两套衣服、两双鞋、两种头部或手部部件。验收：切换后动作继续播放；颈部、腕部没有裂口；头发与肩膀、裙摆与腿在约定动作中没有明显穿插。
3. **视觉与性能检查**：检查四个朝向及动作中间帧；在 iPhone Safari 和 Android Chrome 实机检查加载、操作和发热。初步目标是单角色运行稳定达到 30fps，60fps 为优化目标；这属于验收目标，尚无实测结果。
4. **接回游戏**：人物验证页通过后，将同一角色系统用于装扮和家园，接入搭配保存与图片导出，再扩充素材数量。

首轮应先验证一个角色能否同时做到“好看、可转身、可换部件、动作正常”，再批量制作八款发型。现有房间背景、底栏、货币、家具和二合逻辑可以继续复用，人物渲染与换装逻辑需要重做。
